# verify-ai-adversarial

promptfoo's official red-team skills, vendored unchanged, plus three constraints for our teams:

1. **Fully offline** from promptfoo's cloud. It is enforced and proven, not just requested.
2. **An approved corpus**: 60 multi-turn Crescendo goals generated by promptfoo, in tiers of 20/20/20.
3. **One commented config** for target, attacker and judge over OpenAI-compatible endpoints.

Crescendo runs to a depth of 10 with backtracking. Guardrail handling is optional.

## Skills

| Skill | Source | Role |
|---|---|---|
| [redteam-offline](skills/redteam-offline/) | this repo | Entry point: preflight, config, offline run, verification, recording |
| `promptfoo-provider-setup` | promptfoo, vendored verbatim | Connecting non-OpenAI targets (HTTP, JS, Python) |
| `promptfoo-redteam-setup` | promptfoo, vendored verbatim | Scoping discipline: purpose, identities, trust boundaries |
| `promptfoo-redteam-run` | promptfoo, vendored verbatim | Reading results, ASR, reruns, CI gates |

The vendored skills are pinned in `UPSTREAM.lock` (promptfoo commit `d833727`, plugin 0.1.3, MIT,
`LICENSE-promptfoo`). CI fails if they are ever edited. To update, run `scripts/sync-upstream.sh <ref>`,
review the printed diff, and rerun the smoke test. Where they say `--remote`, cloud login, `validate target`,
`redteam generate/run` or hosted strategies, `redteam-offline` wins and the hook blocks the command. Do not
also install the separate `promptfoo@promptfoo` plugin, because the skill names would collide.

## What we add on top of promptfoo, and why

| Addition | Why promptfoo alone is not enough |
|---|---|
| `corpus/` (approved goals) | Generating goals needs promptfoo's cloud. Teams must run offline and comparably. |
| `scripts/verify-offline.sh` + `net_wrapper.cjs` | Sets promptfoo's offline flags. Refuses cloud commands. Blocks every request to a host outside the allow-list, including the telemetry beacon promptfoo sends even when telemetry is off, and exits 3 on any unexpected attempt. |
| `scripts/corpus-tests.mjs` | Writes the corpus tests with Crescendo settings from the app's config. It refuses remote-only strategies, `maxTurns` > 10, and a missing purpose or attacker. |
| `hooks/promptfoo_offline_gate.sh` | Blocks `--remote`, cloud login, `share`, `validate target`, `redteam run/generate`, and any eval outside the wrapper. Enforcement, not prose. Active on plugin install in Claude Code (`hooks/hooks.json`), Copilot CLI (`com.github.copilot/hooks/hooks.json`, verified live 2026-10-05) and Cursor (`com.cursor/hooks/hooks.json` via the generated `.cursor-plugin/plugin.json`, not live-verified). Codex loads no hooks from spec plugins. |
| `skills/redteam-offline/templates/redteam.yaml` | One config with every setting. Optional toggles are commented and explained. |
| `templates/guardrail-transform.js` + `to-messages.js` (optional) | Grades HTTP 400/403 and canned-text guardrail blocks instead of counting them as transport errors. A 401 is always an error. |
| `scripts/summarize-results.mjs` (optional) | Per-plugin pass/fail/blocked/error and cross-app comparison. |
| `scripts/smoke/` | End-to-end offline proof, rerun on every promptfoo upgrade. |

## Why tests are written to a file

Settings from `redteam.yaml` reach promptfoo's own Crescendo provider by writing `tests.generated.yaml` next to
the config. That is the same shape `promptfoo redteam generate` emits. Two native-looking alternatives fail in
promptfoo 0.123.1 (details in [offline-mode.md](skills/redteam-offline/references/offline-mode.md)):

- **Crescendo in `defaultTest`:** promptfoo also treats it as the grader, so every grader breaks.
- **A JS test generator:** the attack silently runs one turn, or the judge falls back to promptfoo's default model.

## Verified (promptfoo 0.123.1, 2026-09-23)

| Claim | Evidence |
|---|---|
| All 60 goals run 10 Crescendo rounds with backtracking, offline, `errors=0` | `scripts/smoke/smoke-test.sh <dir> 1,2,3 10`: 60 × 10 rounds, 299 backtracks; only `localhost` reached, promptfoo's telemetry beacon blocked by the wrapper |
| Attacker and judge calls reach only the configured aliases | Same run: the mock logged only `attacker-model` and `judge-model` |
| `{{env.*}}` renders everywhere under the wrapper, including inside Crescendo | Smoke stage C, plus a nested-attacker check (see offline-mode.md, gotcha 2) |
| Guardrail 400 = blocked, 401 = error, benign = pass | Smoke stage A, plus 10 classifier cases in `tests/adversarial/test_scripts.sh` |
| Corpus is promptfoo's output, reproducible, 20/20/20, tagged, manifest in sync | `tests/adversarial/test_scripts.sh`, 52 checks, in CI |
| Hook and wrapper refuse cloud-bound commands | same suite |

Not exercised here: a real target, a real attacker model's refusal rate, and `stateful: true` session apps.

## Quick start

```bash
npm i -D promptfoo@0.123.1
bash plugins/verify-ai-adversarial/scripts/smoke/smoke-test.sh      # expect SMOKE OK
# then: "red team <app> offline" → redteam-offline
```

Egress policy on scan runners should block `api.promptfoo.app`, `r.promptfoo.app`, `a.promptfoo.app` and
`api.promptfoo.dev`.
